# Training-free in-context adaptation for VLAs (GR00T-N1.5 and pi0.5)

Test-time, training-free in-context learning (ICL) for two vision-language-action policies,
evaluated on LIBERO-Plus (LIBERO-Long / `libero_10` perturbation suite). Nothing is trained:
a small memory is built from a few clean demonstrations, and at test time the closest demo
frames are retrieved by visual similarity and their context is fed back to the policy.

This repository is the RA-VLA reproduction codebase (GR00T-N1.5 + LIBERO tooling) plus the ICL
code. The ICL files are listed below; everything else is the base code they import.

## Method

1. **Memory.** For each of the 10 LIBERO-Long tasks, 3 demonstrations are sampled (seed 0) and
   every 4th frame is passed through the frozen policy (2,039 frames). Per frame we store:
   - **key**: a visual-only embedding, mean-pooled and L2-normalised
     - GR00T: VLM (layer 12) hidden states at the image-token positions. Images precede the
       instruction and the LLM is causal, so these states have not seen the text.
     - pi0.5: SigLIP image tokens (the prefix is bidirectional, so LLM states would see text).
   - **VLM embedding** of the frame (GR00T: backbone token sequence; pi0.5: prefix embeddings);
   - **actions generated by the policy's own action head** for that frame (not ground truth).
2. **Retrieval.** A new (OOD) observation goes through the VLM; its key retrieves the top-k
   memory frames by cosine similarity.
3. **Use of the retrieved context** — three variants:
   - `concat` (k=1): retrieved VLM embedding appended to what the action head attends to
     (GR00T: DiT cross-attention sequence; pi0.5: per-layer KV cache), and the retrieved action
     chunk embedded with the head's own action encoder and prepended to the action tokens.
   - `retrieved`: majority vote of the top-5 frames' task; its clean training instruction is
     appended to the OOD instruction (`"<ood instruction>. <retrieved instruction>"`).
   - `generated`: a separate VLM (Qwen3-VL-30B-A3B) sees the retrieved demo frame + its
     instruction and the current view, writes one sentence restating the task, appended.
     (GR00T's own VLM keeps only 12 LLM layers and cannot generate text.)
   The text is fixed at the first call of an episode. `k=0` / `text_mode=none` is the stock policy.

## Environments

- **GR00T**: the GR00T-N1.5 environment (transformers 4.51.3, PyTorch); `dtaidistance` on `PYTHONPATH`.
- **pi0.5**: an [openpi](https://github.com/Physical-Intelligence/openpi) checkout's `.venv` (JAX 0.5.3);
  run with `PYTHONPATH=<this repo>` so `pi05_icl` imports.
- **Simulator client**: LIBERO-Plus + robosuite 1.4 env (see `env_eval.sh`); rendering via OSMesa.
  With software rendering set `LP_NUM_THREADS=2` per client, otherwise each client spawns ~1 thread
  per core per camera and many clients oversubscribe the CPU.
- **Hint VLM** (only for `generated`): transformers >= 4.57, ~60 GB GPU.

## Reproducing

GR00T (checkpoint `youliangtan/gr00t-n1.5-libero-long-posttrain` in `models/public_finetunes/libero_long_posttrain`,
dataset `IPEC-COMMUNITY/libero_10_no_noops_lerobot` in `datasets/libero_10`):

```bash
source env.sh
$CONDA_PY scripts/rag/6_build_icl_memory.py            # -> models/icl/libero_10/memory.pt (4.4 GB)
./run_icl_eval.sh 1 5                                   # stage 1: pre (k=0) vs concat (k=1), 10 variants
./run_icl_text_eval.sh pre retrieved                    # stage 2 text arms, 20 variants
./run_icl_text_eval.sh generated                        # needs 8_serve_hint_vlm.py on :8890
VARIANTS=all NUM_CLIENTS=20 SERVERS_PER_ARM=2 ./run_icl_text_eval.sh retrieved   # stage 3, 2,519 variants
```

pi0.5 (official `pi05_libero`; trained on all four LIBERO suites; 10-step chunks, 5 executed per call):

```bash
python scripts/pi05/fetch_checkpoint.py                 # -> /dev/shm/openpi_cache/.../pi05_libero (12.4 GB)
$CONDA_PY scripts/pi05/0_export_demo_frames.py          # GR00T env; same 2,039 frames as the GR00T memory
PYTHONPATH=$PWD <openpi>/.venv/bin/python scripts/pi05/1_build_memory.py   # -> /dev/shm/pi05_icl/memory.npz (6 GB)
./run_pi05_icl_eval.sh stage1 eval_results/icl/variants10.json pre concat
./run_pi05_icl_eval.sh stage2 eval_results/icl/variants20.json pre retrieved
LP_NUM_THREADS=2 NUM_CLIENTS=24 SERVERS_PER_ARM=2 ./run_pi05_icl_eval.sh full all pre retrieved
```

Use `PORT_OFFSET` when running several `run_pi05_icl_eval.sh` at once. Every run writes a
`run_manifest.json`; resuming into a directory with a different configuration is refused.

Gripper conventions: the LIBERO datasets store 1 = open / 0 = closed, pi0.5 outputs -1 = open /
+1 = closed, and the client applies `sign(1 - 2x)`; the pi0.5 server therefore sends `(1 - g) / 2`.

## Results (LIBERO-Plus, `libero_10`, 1 episode per variant, seed 0)

| Stage | GR00T-N1.5 | pi0.5 |
|---|---|---|
| Offline, clean frames: action MSE, stock -> concat | 0.00064 -> 0.01412 | 0.0019 -> 0.0281 |
| 1. concat, 10 variants | 9/10 -> **0/10** | 8/10 -> **0/10** |
| 2. retrieved text, 20 variants | 11/20 -> 12/20 | 13/20 -> 10/20 |
| 2. generated text, 20 variants | 11/20 -> 10/20 | not run |
| 3. retrieved text, full suite (paired) | 78.3% -> 72.3% (350 variants, p=0.005) | 83.3% -> 75.8% (1,859 variants, p=1e-15) |

GR00T's stage-3 baseline is an earlier 350-variant run of the stock checkpoint with the same client
and settings (8 actions per call). pi0.5's baseline and retrieved runs share the protocol
(5 actions per call); the baseline was stopped at 1,859 variants, so the paired comparison covers
those. None of the training-free variants improved either policy: concatenation breaks the frozen
action head, and appended text lowers success on most perturbation axes (largest drop:
Background Textures, pi0.5 95.2% -> 79.2%). Top-1 retrieval picks the correct task ~83-87% of the
time; wrong retrievals append a contradicting instruction.

## Adapting to a real robot

The method code is robot-agnostic; the LIBERO-specific parts are:
the checkpoints; GR00T's data config / modality keys (`LiberoDataConfig`,
`annotation.human.action.task_description`, `video.image`); `pi05_icl` hard-codes
`get_config("pi05_libero")` and drops the always-masked right-wrist camera slot (`DROPPED_SLOT`);
`serve_pi05_icl.py` maps GR00T keys to openpi LIBERO inputs and converts the gripper for this
client; `0_export_demo_frames.py` reads its frame list from the GR00T memory (write an exporter
from your own dataset instead); and default paths (`/dev/shm/...`, `models/...`).
